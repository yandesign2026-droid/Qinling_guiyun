缺口诊断

一、现在能进引擎吗Readiness

差一层，但只差一层。把内容与生产要素堆成六层看：

层内容状态说明
结构层25 节点的依赖与产出已有可以直接翻译成引擎流程图
数值层变量、阈值、判定逻辑已有12 个全局变量 + 三档结局门槛，够用
角色层11 角色的执念与功能已有每个角色都对应一个动词，已过滤过
剧情层七天节拍与三结局定义已有分镜脚本 P10–P11 已完整定义 A/B/C/E9
文本层对白、选项、旁白、UI 文案缺唯一硬卡点。四个证人 × 四状态 + 问句库 + 老板娘半真半假信息源
资产层场景图、立绘、视频、音效缺缺一份《视觉与音效设定》，也缺资产清单
运行层引擎 + 拟真手机界面缺还没有一行能跑的东西

关键判断：不要被《口径冲突补丁》里那 8 项待决卡住。其中只有 03 涂血和 08 第 4 个节点会影响少量台词，其余 6 项改的是数值表和节点表，不影响你先动笔。现在可以写的台词约占全剧 80%，等框架跑起来再回头补。

二、这套设计的技术形态是什么Shape of the Thing

不是视觉小说。看节点里的交互方式：支付房费要输金额、照片要双指放大、六张照片拖到时间轴排序、卦象卡拖到红点、收音机拖频率指针、地图看六阵眼、怀表看内侧刻字——这是一套拟真手机 / 桌面界面的操作。

加上非叙述节点：N17 收音机 30 秒视频、N19 井边反转视频、N21 三结局专属视频过场。所以它的形态是：

「手机拟真 UI 为主 + 少量视频节点」的调查推理互动叙事，参照系是《流言侦探》那一类，不是《隐形守护者》，也不是 Ren'Py 那种对话框在屏幕下方的视觉小说。

这个判断直接决定了工具选型——详见下一页。

三、工具与模型选型Tool Selection

选型前提：国内可用、单人可操作、成本可控、能长成正式产品。

环节首选备选理由
台词起草Claude / GeminiGPT、DeepSeek要同时记住 11 个角色各自的说话方式与「绝对不能说什么」。老板娘的不可信靠「说得太多太顺」，这种分寸 AI 起草后必须你亲手过一遍
分支逻辑Ink + inkjsTwine（最快）/ Yarn Spinner（进 Unity）你这套有 12 个全局变量、三档结局门槛、证人状态序列。Ink 的 VAR / knots / 条件分支就是为这种结构设计的，纯文本脚本也方便版本管理
前端界面HTML / CSS / JS + inkjsUnity + Ink Unity Integration你要的拟真交互（拖拽排序、捏合缩放、拖指针、输入金额、手机震动）全是前端原生能力。上 Unity 反而要把每套交互重新造一遍。先做网页 Demo，验证后要上架再考虑打包
静态图即梦 Seedream / Nano Banana ProMidjourney第一要求不是漂亮，是同一张脸的多个状态一致。先用参考图把 11 张脸锁死，再批量生成状态
视频节点Seedance 2.5（即梦入口）可灵 Kling 3.0原生 4K、单条最长 30 秒、支持多图参考锁角色、国内可用且有每日免费额度。可灵性价比更高、动作更自然，做井边那种人物运动好用。Veo 3.1 / Sora 2 质感好，但国内可用性是现实问题，不建议作为主力
语音Azure TTS / 剪映 / ElevenLabs真人 CV（预算充足时）周教授从头到尾只有声音，「找了三十年只找到频率」全靠声线撑，值得单独定一条音色，别和其他角色共用
音乐音效Suno + 剪映音效库Artlist环境音清单里那几项（雾中风声、墙里抓挠、19 米波段杂音、脚步材质从羊毛地毯到石板再到水泥的变化）是这类游戏的命，别省钱
发行先网页 Demo，再决定TapTap / Steam / 微信小程序网页 Demo 能最快拿到真实反馈。别急着定发行渠道——先知道这东西有没有人愿意玩完

不建议：Ren'Py。它是做视觉小说的，对话框在屏幕下方、分支靠菜单。你这套要的是全屏拟真 UI 与自由探索，用 Ren'Py 会把你逼回 VN 的形态，等于改设计。

排期

六、三条轨并行，不是串行Parallel Tracks

轨做什么依赖谁产出
A 文本台词库 B谁都不依赖4 证人 × 4 状态全量对白、陈素心问句库、老板娘「半真半假」信息源表、道具与 UI 文案
B 技术UI 壳 + 状态机只依赖 A 的节点框架用占位图先把交互跑通：支付、抽屉、照片放大、拖拽排序、拖指针、证据板
C 资产风格设定 → 出图出视频依赖 A 定下角色状态《视觉与音效设定》→ 11 张脸锁定 → 场景 → 道具 → 视频节点 → 音频

B 轨不要等 C 轨。用灰色方块当占位图，先把交互手感做出来。这条错了很多团队：先画三个月图，最后发现交互不对，图全废。

七、第一周：Day1 垂直切片Vertical Slice

按「最小可玩集」的思路，先做 N01–N04 四个节点，约 10 分钟流程。这四个节点刚好覆盖全部核心技术难点：

节点要做什么验证的技术点
N01前夜入村氛围层：视频/图层叠加速度、手机震动 API、环境音混入
N02入住登记拟真支付（输入金额）、抽屉点击、埋点①是否写入 mention_watch
N03遗照发现双指放大、查看日期触发 E1、证据入袋动画
N04墙里抓挠黑屏 + 音效 + 震动组合、质询三选一、st_boss 状态变化、证据板点亮

做完这个切片就知道了：① 这套拟真 UI 的手感对不对；② 后面 21 个节点的真实工时是多少（现在任何排期都是猜的）；③ 你要不要继续自己做，还是该找技术合伙人；④ 还要不要保留视频节点——那段成本占三分之一。

八、四个坑Risks

角色一致性是最大坑。陈素心与老板娘共用一具身体，切换靠「脖子僵→眼左下→肩收背弓→指节蜷→声下掉」这套身体信号。跨几十张图保持同一张脸，必须用参考图锁定工作流，别指望一次生成。
别一口气生成全剧资产。先用 Day1 切片跑通，确认视觉方向，再批量出。全剧 58 张图一次性做完，方向错了就是全废。
体量要现实。60–90 分钟对单人来说是很大的工程量。先完成 18 节点最小可玩集（35–45 分钟），完成本身就是胜利，剩下的慢慢补。
题材要先过合规。摄魂、遗照、井底封阵、民间信仰这类内容，若要上国内平台公开发行，建议先了解目标渠道的审核口径，避免做到一半被打回。
